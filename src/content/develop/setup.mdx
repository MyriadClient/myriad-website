# Setting up

You need JDK 25 and Git. Gradle comes with the project (`./gradlew`).

<Steps>
### Create the project

Use the [addon template](https://github.com/MyriadClient/myriad-addon-template) (GitHub's **Use this template**), or
clone it.

### Rename it

- the mod id `my-addon` in `src/main/resources/fabric.mod.json`, in `settings.gradle`, and in the mixin config's file
  name (`my-addon.mixins.json`);
- the package `com.example.addon` and the class `MyAddon`;
- `maven_group` and `archives_base_name` in `gradle.properties`.

### Run it

```bash
./gradlew runClient
```

Minecraft starts with Myriad, Essentials and your addon (`-PopenDesktop` opens the menu over the title screen).

### Build it

```bash
./gradlew build
```

The jar is in `build/libs/`.
</Steps>

## The build

The template builds with Myriad's Gradle plugin, so `build.gradle` holds only what's yours:

```groovy filename="build.gradle"
plugins {
    id 'dev.myriadclient.addon' version '0.10.0'
}

version = project.mod_version
group = project.maven_group

base {
    archivesName = project.archives_base_name
}
```

The plugin's version is the Myriad release you build against. It comes from Myriad's maven, which `settings.gradle`
lists under `pluginManagement`, and it sets up:

- **Loom, Minecraft, Fabric and Myriad** at the versions that Myriad release was built with. To override one, set
  `minecraft_version`, `loader_version`, `fabric_api_version` or `myriad_version` in `gradle.properties`.
- **Myriad's maven** (`https://maven.myriadclient.dev/releases`), for `dev.myriadclient` only. It has
  `dev.myriadclient:myriad` with sources and javadoc, so your IDE shows the javadoc of every API class.
- **Essentials in the dev client** when `essentials_version` is set in `gradle.properties`. Essentials is never on
  your compile classpath, so your code can't come to depend on it: players can remove it.
- **`checkApiOnly`** before every compile. It fails the build if your code references `dev.myriadclient.impl`.
- **Java 25**, a sources jar, and `${version}`, `${myriad_version}` and `${minecraft_version}` filled in
  `fabric.mod.json`.
- **Publishing**: a maven publication named after `archives_base_name`. `./gradlew publishToMavenLocal` publishes it
  locally; `./gradlew publishAddon` builds and tests, then publishes to Myriad's maven (with the `myriadUsername` and
  `myriadPassword` properties, which official addons have). To release to players, see
  [Publishing](/docs/develop/publishing).

Your own repositories, dependencies and settings go in `build.gradle` as usual.

To build against Myriad changes that aren't released yet, keep a Myriad checkout next to your project, build core's jar
there (`./gradlew :core:jar`) and build with `-PcoreDir=../myriad`. Both the plugin and core then come from that
checkout, with nothing to publish.

## `fabric.mod.json`

```json
{
  "schemaVersion": 1,
  "id": "my-addon",
  "version": "${version}",
  "name": "My Addon",
  "description": "What it does, in one line.",
  "authors": ["You"],
  "icon": "assets/my-addon/icon.png",
  "contact": {
    "sources": "https://github.com/you/my-addon",
    "issues": "https://github.com/you/my-addon/issues"
  },
  "environment": "client",
  "entrypoints": { "myriad": ["com.example.addon.MyAddon"] },
  "mixins": ["my-addon.mixins.json"],
  "depends": { "myriad": ">=0.9.0", "minecraft": "~26.2" }
}
```

- `entrypoints.myriad` is your [`MyriadAddon`](/docs/develop/addon).
- `contact.sources` pointing at your GitHub repository lets Myriad [update your addon](/docs/develop/publishing).
- `depends.myriad` is the oldest Myriad you support (see [Compatibility](/docs/develop/compatibility)).

## The dev client

`./gradlew runClient` starts the game with Myriad's dev checks on: a core service called off the render thread is
logged, and `.bench` measures core's hot paths. Switches:

| Switch | Does |
|---|---|
| `-PopenDesktop` | opens the menu over the title screen |
| `-PquickPlay="New World"` | loads straight into a singleplayer world |
| `-PquickPlayServer=localhost:25565` | joins a server (with `-Pusername=Name` to play as that name on an offline server) |
| `-PscreenshotEvery=10` | saves a screenshot every 10 s into `run/screenshots` |
| `-PauditMixins` | applies every mixin at start, so a bad target fails at once |
| `-PrunDir=run2` | uses another game directory, for a second client beside the first |
| `-Photswap` | runs on the JetBrains Runtime with a debug port (5005, or `-PdebugPort`), so recompiled classes swap in without a restart |
| `-PessentialsDir=../myriad-essentials` | uses the Essentials jar built in that checkout |
| `-PnoEssentials` | leaves Essentials out |

The **dev console** reads commands from `run/myriad-dev-inbox` (one per line) and logs what happens: Myriad commands,
`hold forward,sprint 20`, `look <yaw> <pitch>`, `wait <ticks>`, `screenshot <name>`, `menu open`, `panel <id>`, and
`selftest` (turns every module on and off and reports any that throw). See [Testing](/docs/develop/testing).

<Callout type="warning">
  Only use `dev.myriadclient.api`. Anything in `dev.myriadclient.impl` is internal and changes without notice; an
  addon that touches it breaks on the next release.
</Callout>
