# Services

Services are one shared implementation of the hard things, so addons don't fight over the same state (two modules
both rotating, both switching slots) and don't each get anti-cheat details wrong. Use them instead of sending packets
yourself. Their internals keep up with servers and anti-cheats from release to release; the calls stay the same.

Every service is on `Myriad` (`Myriad.rotations()`, …). Calls that act on the player take an **owner** (your module):
what it asked for is dropped when it turns off, and [hooks](/docs/develop/hooks) can tell callers apart.

## Options and the anti-cheat profile

Services that act take an immutable `Options`. Start from a preset and change what you need:

```java
Placement.Options opts = Placement.Options.forServer().withRange(5).withSwing(false);
```

`forServer()` follows the player's [anti-cheat profile](/docs/use/anti-cheat): careful where the server checks,
quick where it doesn't. Don't add a "Strict" setting to your module: use `forServer()`, or ask the profile what the
server checks:

```java
AntiCheat.Profile p = AntiCheat.inEffect();   // works before Myriad has started too (then Grim: be careful)
if (p.simulatesGlide()) return;                 // this flight would be set back here
```

| `AntiCheat.Profile` answer | Means | What follows from it |
|---|---|---|
| `simulatesMovement()` | the anti-cheat runs your movement and compares (Grim) | `Rotations.Options.forServer()` uses the move fix; `isStrict()` |
| `checksLookOnActions()` | every click is checked against the rotation the server last got | placements turn first; a building places one block a tick |
| `visibleFacesOnly()` | placements must click a face you can see | `Placement.Options.forServer()` picks visible faces |
| `clicksOnlyWhileStill()` | inventory clicks are refused while you move or sprint | `Inventory.safeToClick()` waits for a still moment |
| `simulatesGlide()` | the elytra glide is simulated | non-vanilla flight is set back; No Durability swaps a chestplate on |
| `breakTiming()` | `SERVER` (the vanilla 70% rule) or `CHECKED` (timed from the start, as Grim does) | `Breaking.Options.forServer()` is `FAST` or `PACKET` |
| `interactionBudget()` | uses, placements and attacks per 300 ms | the packet budget for `INTERACT` (9: Paper drops the tenth) |

Myriad has `VANILLA`, `GRIM` and `NCP`. An addon for a server that checks things its own way registers a profile
and, if it can tell the server, answers the `AntiCheat.DETECT` hook so Auto picks it:

```java
AntiCheat.Profile mine = AntiCheat.Profile.GRIM.named("my-addon:my_server", "My server").withSimulatesGlide(false);
ctx.registerAntiCheatProfile(mine);
ctx.hook(AntiCheat.DETECT)
    .named("My server")
    .handle(call -> "play.myserver.net".equals(call.input().host()) ? mine : call.proceed());
```

## Rotations

Per-tick rotation requests, arbitrated per axis (pass `Float.NaN` for an axis you don't need), the highest priority
winning. The camera isn't moved; the rotation goes to the server.

```java
@Subscribe(inGame = true)
private void onTick(TickEvent.Pre e) {          // request in Pre so move fix covers this tick's movement
    Myriad.rotations().lookAt(this, target.getEyePosition(), Rotations.PRIORITY_HIGH,
        Rotations.Options.forServer().withTurnSpeed(turnSpeed.get()));
}
```

- `Options.withTurnSpeed(degreesPerTick)` turns gradually and eases back afterwards; `withMoveFix(true)` walks along
  the sent yaw (what Grim expects).
- `request(owner, yaw, pitch, priority, options, afterSent)`: `afterSent` runs once the rotation has gone out, the
  moment to act with it.
- `serverYaw()`, `serverPitch()`, `isRotating()`, `rotationForAction()` (the rotation this tick's packet will carry).

## Inventory

| | |
|---|---|
| `select(slot)`, `silentSwap(slot, action)` | switch the held slot; or do something with another slot for one action, invisibly |
| `hold(owner, slot, ticks)` / `holdWeakly` / `release(owner)` | hold a slot on the server for a while (mining runs at its speed) |
| `findInHotbar(pred)`, `findInInventory(pred)`, `bestInHotbar(score)`, `count(pred)` | find items |
| `moveToHotbar`, `ensureInHotbar(pred, preferred)`, `pullToHotbar`, `borrow(owner, index, replaceable)` / `giveBack` | bring items to hand |
| `move`, `merge`, `swapWithOffhand`, `quickMove`, `drop` | inventory clicks |
| `safeToClick()`, `prepareClick()` | Grim cancels inventory clicks while you move: check, or release your keys for a tick |
| `spare(owner, pred)` | ask other modules to leave some items alone (worn-out tools) |
| `attackCharge()`, `serverItem()`, `serverSlot()` | what the server thinks you hold |

```java
int sword = Myriad.inventory().findInHotbar(ItemInfo::isWeapon);
if (sword >= 0) Myriad.inventory().silentSwap(sword, () -> Interactions.attack(target, true));
```

## Placement

```java
Placement.Attempt a = Myriad.placement().place(this, pos, slot, Placement.Options.forServer());
if (!a.sent()) warn("Can't place there: " + a.check());   // OUT_OF_RANGE, ENTITY_IN_WAY, NOT_VISIBLE, ...
a.result().thenAccept(placed -> { if (!placed) retryLater(pos); });   // once the server kept or refused it
```

Neighbour clicks, silent swap, visible faces first, rotation through `rotations()` when the options rotate.
`check(pos, options)` says why not without trying. `clickTargets(pos)` and `place(owner, hit, slot, options)` for when
the clicked face matters (stairs, logs, slabs).

## Breaking

```java
Breaking.Attempt a = Myriad.breaking().breakBlock(this, pos, priority, Breaking.Options.forServer());
```

Queues by priority across modules, picks and holds the fastest tool on the server, batches instant breaks, shows the
crack, rotates if asked. Modes: `VANILLA` (like the attack button), `PACKET` (finishes the moment the server allows),
`FAST` and `FAST_GRIM` (2b2t-style decoy starts), with `withDoubleBreak` to mine a second block meanwhile.
`progress(pos)`, `isPending(pos)`, `cancel(owner)`.

## Building

Describe a shape as a `Blueprint` of `Target`s; `building()` breaks and places what's in reach each tick in a working
order.

```java
Blueprint wall = Blueprint.box(from, to, Target.block(Blocks.OBSIDIAN));
Build build = Myriad.building().start(this, wall, Building.Options.forServer().withKeepUp(true));
build.finished().thenAccept(done -> info(done ? "Built" : "Stopped"));
```

`Target.air()`, `solid()`, `block(b)`, `anyOf(...)`, `state(blockState)` (orientation included). `Blueprint.of(map)`,
`box`, `dynamic(supplier)`. `Build.steps()` says what's happening at each position or why it's stuck (`NO_ITEM`,
`FLUID`, `WRONG_ANGLE`, ...); `keepUp` maintains the shape (surround).

## Containers

```java
Myriad.containers().open(chestPos, 40).thenAccept(view -> {
    int slot = view.find(s -> s.is(Items.GOLDEN_APPLE));
    if (slot >= 0) view.quickMove(slot);
    Myriad.containers().close();
});
```

A shulker box or ender chest from your inventory opens where you stand: `openItem(owner, index, ticks, options)`
puts it down beside you (turned first where the server checks looks), opens it, and gives you an `ItemSession`;
`session.finish()` closes it, breaks it (with your Silk Touch pickaxe for an ender chest), picks it up and puts it back
in its slot. Putting it back is Myriad's own job, so it finishes even if your module turns off, and a box put down but
not opened is picked back up too. From a job, `Steps.inItem(index, view -> step)` does the whole round trip:

```java
Myriad.jobs().start(this, Steps.inItem(index, view -> Steps.put(view, this::isLoot, Containers.Transfer.all())));
```

## Work over several ticks

Long-running work (open, take, close; build until done; fly a route) is a [job](/docs/develop/jobs): a `Step` you
start with `Myriad.jobs().start(this, step)`, with the services above as ready-made steps in `Steps`. Delays and
repeats are `Myriad.jobs().later(this, ticks, action)` and `every(this, ticks, action)`. `Myriad.tasks()` still
works, deprecated, until 1.0.

## The rest

| | |
|---|---|
| `Myriad.limits()` | the shared packet budget: `canSend(kind, n)`, and `urgent(action)` for must-happen actions (totems) |
| `Myriad.antiCheat()` | `profile()` and its answers, `detected()`, `choice()`/`choose(profile)`, `profiles()` |
| `Myriad.tickSpeed()` | client tick speed per owner (`set(owner, multiplier)`), multiplied together, cleared on disable |
| `Myriad.server()` | TPS, ping, address, `isLagging(ms)`, `rubberbandedWithin(ms)`, `reconnect()` |
| `Myriad.elytra()` | the elytra engine: `noDurability(owner)`, `chestSwap()`, `glideHold()`, `addPilot(...)`; `GlideEvent` |
| `Myriad.friends()` | `isFriend(player)` |
| `Myriad.controls()` | control panels: list, switch, create |
| `Myriad.shares()` | [shared configs](/docs/develop/sharing) |
| `Myriad.hooks()` | [hooks](/docs/develop/hooks) in effect |

## Helpers

Static helpers so addons don't each re-derive the same things (all under `dev.myriadclient.api`):

| | |
|---|---|
| `combat.Targets`, `combat.TargetSettings` | finding entities with shared rules (hostile, friends, invisible, walls), sorted |
| `combat.Damage`, `combat.Threats`, `combat.Crystals`, `combat.Trajectory` | explosion and melee damage, what could kill you, crystal spots, projectile paths |
| `world.Holes`, `world.ChunkCache`, `world.BlockScan` | holes and surrounds; per-chunk work; fast block search |
| `util.Entities`, `util.BlockInfo`, `util.ItemInfo` | facts about entities, blocks and items |
| `util.Reach`, `util.Interactions`, `util.Packets`, `util.Mining`, `util.Movement` | reach and line of sight; attacking, using, swinging; sending packets; mining speed; movement keys and speed |
| `util.Positions`, `util.MathUtil`, `util.Slots` | spheres and boxes of positions; angles and vectors; slot indexes |
| `util.Timer`, `util.RateCounter`, `util.Format`, `util.Texts`, `util.Ticks`, `util.TickCached` | timing and formatting; a value worked out once per tick |
| `util.Async`, `util.Http` | the worker pool (and back to the render thread); GET/POST/DELETE with JSON |
| `util.Baritone` | drive Baritone when it's installed, without depending on it |
| `util.FakePlayers` | client-side dummy players for testing |

</Callout>
