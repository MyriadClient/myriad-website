# Settings

Settings are typed fields on a module, built with a fluent builder from a **group**. They're saved with the player's
profile (only values that differ from the default), edited in the menu and with `.set`, and shared in
[shared configs](/docs/develop/sharing).

```java
public final class Nuker extends Module {
    private final DoubleSetting range = sgGeneral.decimal("Range")
        .description("How far to break blocks.")
        .defaultValue(4.5)
        .range(0, 6)                 // the hard limits
        .decimals(1)
        .build();
    private final EnumSetting<Mode> mode = sgGeneral.oneOf("Mode", Mode.ALL).build();
    private final RegistryListSetting<Block> blocks = sgGeneral.blocks("Blocks")
        .defaultValue(Blocks.STONE, Blocks.DEEPSLATE)
        .visible(() -> mode.get() == Mode.LIST)   // shown only when it matters
        .build();

    private final SettingGroup sgRender = settings.group("Render");   // later groups start folded
    private final ColorSetting color = sgRender.color("Color")
        .defaultValue(SettingColor.role(SettingColor.Mode.RED))       // follows the theme
        .build();

    public enum Mode { ALL, LIST }
    ...
}
```

Read a value with `get()`. Settings are fields like any other: keep them `private final`, or `public final` when
another class (a mixin, a [control panel preset](/docs/develop/control-panels)) needs them.

## Every type

Before 0.8 the number and enum builders were `intSetting`, `doubleSetting` and `enumSetting`; they still work,
deprecated, until 1.0.

| Builder (on a group) | Type | Value |
|---|---|---|
| `bool(name)` | `BoolSetting` | `boolean` |
| `integer(name)` | `IntSetting` | `int`; `.range(min, max)`, `.sliderRange(min, max)` |
| `decimal(name)` | `DoubleSetting` | `double`; `.range`, `.sliderRange`, `.decimals(n)`; `getFloat()` |
| `oneOf(name, default)` | `EnumSetting<E>` | an enum constant (shown title-cased) |
| `choice(name, () -> options)` | `ChoiceSetting` | one of a list worked out at runtime |
| `string(name)` | `StringSetting` | text |
| `stringList(name)` | `StringListSetting` | lines of text |
| `color(name)` | `ColorSetting` | a `SettingColor`: fixed, rainbow, or a theme role; `.argb()` |
| `keybind(name)` | `KeybindSetting` | a key or mouse button; `wasPressed(event)` |
| `action(name, runnable)` | `ActionSetting` | a button |
| `blocks`, `items`, `entityTypes`, `statusEffects`, `registryList(name, registry)` | `RegistryListSetting<T>` | a set of registry entries, with a picker |
| `item(name, default)`, `block(name, default)`, `sound(name, default)`, `registry(name, registry, default)` | `RegistrySetting<T>` | one registry entry |
| `enumSet(name, Enum.class)` | `EnumSetSetting<E>` | any number of an enum's constants |
| `intList(name)` | `IntListSetting` | whole numbers |
| `modules(name)` | `ModuleListSetting` | other modules ("pause while these are on") |
| `blockPos(name)` | `BlockPosSetting` | a position, with a **Here** button |
| `file(name)` | `FileSetting` | a path, with the system file picker |

Every builder has `.description(text)`, `.defaultValue(v)`, `.visible(() -> bool)`, `.onChanged(v -> ...)` and
`.protect()`, then `.build()`, which adds the setting to the group.

Every type keeps its value through a save and a load, `encode`/`decode`, and (except files, module lists and registry
lists, which show a summary) `.set` with what `valueString()` shows, in any locale. Bad JSON leaves the value as it was
instead of throwing. Core's `SettingRoundTripTest` checks this for each type.

## Standard groups

Some settings mean the same in every module, so core makes them once: the group adds them, with the same names and
descriptions everywhere, and hands back the service's options built on `forServer()` (what the server checks), so a
module never needs a "Strict" setting. Make one as a field, passing the group the settings go in.

| Class | Adds | Gives |
|---|---|---|
| `service.RotationSettings` | Turn Speed (0 turns at once) | `Rotations.Options` |
| `service.PlacementSettings` | Range (capped at what the server allows: `reach()`), Air Place | `Placement.Options` |
| `service.BreakingSettings` | Mode (Packet, or Fast: every block at 70% of its time), Double Break (shown with Fast) | `Breaking.Options` |
| `service.BuildingSettings` | Placement's two, Actions Per Tick, Break Wrong Blocks, and Breaking's two (shown while Break Wrong Blocks is on) | `Building.Options` |
| `combat.TargetSettings` | the Targets group: which entities, angry only, invisibles, friends, through walls, sort | a `Targets.Query` |
| `render.BoxStyle`, `render.HighlightSettings`, `render.EntityGroups` | how boxes and highlights are drawn, for which entities | drawing helpers |

```java
private final RotationSettings rotation = new RotationSettings(sgGeneral);
private final BuildingSettings building = new BuildingSettings(sgGeneral);

Myriad.rotations().lookAt(this, target.getEyePosition(), Rotations.PRIORITY_NORMAL, rotation.options());
Myriad.building().start(this, blueprint, building.options().withKeepUp(true));
```

Change what your module needs on the options they give with the `with` methods. Add only settings that have more
than one good value; anything with one obvious value is hard-coded (a scaffold places as far as the server allows,
so it has no Range).

## Reacting to changes

```java
private final IntSetting radius = sgGeneral.integer("Radius").defaultValue(32).range(1, 128)
    .onChanged(r -> cache.invalidateAll())      // one setting
    .build();

public MyModule() {
    super(...);
    settings.onAnyChanged(s -> rebuildPlan());  // any of this module's settings
}
```

## Private settings: `protect()`

A setting that holds something private to the player (a webhook URL, a server address, a password, coordinates) must
be marked **protected**. Its value then never goes into a shared config: shares say the setting is there, never what
it's set to, and taking a share in leaves the player's own value alone.

```java
private final StringSetting webhook = sgGeneral.string("Webhook")
    .description("Your Discord webhook URL.")
    .protect()
    .build();
```

`BlockPosSetting` and `FileSetting` are protected already (`.protect(false)` for a position that's a public place).
When in doubt, protect it. See [Shared configs](/docs/develop/sharing).

## A bind inside a module

A `KeybindSetting` that does something while the module is on (a "sub bind"):

```java
private final KeybindSetting pearl = sgGeneral.keybind("Pearl Key").build();

@Subscribe
private void onKey(KeyEvent e) {
    if (pearl.wasPressed(e)) throwPearl();
}
```

`wasPressed` ignores presses while a screen is open. A bind with modifiers needs them held; a bind without any matches
whatever is held, so the player can sneak and press it. Sub binds don't take part in the closest-match rule that
module and control panel binds follow (a press runs only the binds with the most modifiers that match it).

`Keybind.parse` reads a bind the way the menu writes it, which is handy for commands of your own: `Keybind.parse("ctrl+t")`,
`"mouse5"`, `"rmb"`, `"none"` (`Keybind.NONE`); null if it isn't a bind. `Keybind.key(GLFW.GLFW_KEY_T, GLFW.GLFW_MOD_CONTROL)`
builds one in code.

## Layered values

A setting has the player's value (the only one saved) and, on top, **overrides** that code lays for as long as it
needs them. `get()` is the value in effect; `playerValue()` the player's own. This is how control panels work, and how
your code should borrow another module's setting instead of changing it and putting it back.

```java
BoolSetting knockback = (BoolSetting) velocity.settings.get("knockback").orElseThrow();   // by key, as .set takes it

// While flying: lay "off" over whatever the player set. The UI shows it tagged "My Flight".
knockback.override(this, Setting.Layer.MODULE, "My Flight", false);

// Landed: take it off. The player's value shows again; nothing to restore.
knockback.release(this);
// or every override this owner laid on a module's settings:
velocity.settings.releaseAll(this);
```

Layers, lowest first: `SERVER`, `CONTROL_PANEL`, `MODULE`. The highest wins; on ties, the latest. Pass an `editor` to
`override(owner, layer, label, value, editor)` to receive edits the player makes while your override is on top
(control panels save them); without one, edits go to the player's value.

Never write another module's setting with `set(...)` to make it behave: lay an override. Writing changes what the
player saved; an override can't leak.

## Settings of the addon itself

Options that belong to the addon rather than a module (units, a prefix) come from `ctx.settings("Name")`: a `Settings`
shown under the addon in the Addons window and saved with the profile.

```java
AddonSettings units = ctx.settings("Units");
EnumSetting<Unit> distance = units.group("General").oneOf("Distance", Unit.BLOCKS).build();
```

## Your own setting types

Extend `Setting<T>` and register an editor widget for it:

```java
public class RangeSetting extends Setting<RangeSetting.Range> {
    public record Range(double min, double max) {}
    private final double lower, upper;

    public RangeSetting(String name, String description, Range defaultValue, double lower, double upper) {
        super(name, description, defaultValue, (Supplier<Boolean>) null);
        this.lower = lower;
        this.upper = upper;
    }

    @Override protected Range validate(Range v) { ... }          // clamp and order
    @Override public JsonElement toJson() { ... }                 // the player's value
    @Override public void fromJson(JsonElement json) { ... }
    @Override public boolean parse(String input) { ... }         // what .set takes
    @Override public String valueString() { ... }                // how it's shown
}
```

```java
// in initialize:
ctx.settingWidgets().register(RangeSetting.class, s -> {
    HBox row = new HBox(3);
    row.add(new Slider(() -> s.get().min(), v -> s.set(new RangeSetting.Range(v, s.get().max())), s.lower(), s.upper(), 1));
    row.add(new Slider(() -> s.get().max(), v -> s.set(new RangeSetting.Range(s.get().min(), v)), s.lower(), s.upper(), 1));
    return row;
}, false);

// in a module:
private final RangeSetting delay = sgGeneral.add(new RangeSetting("Delay", "A min-max pair.", new RangeSetting.Range(1, 3), 0, 10));
```

<Callout type="info">
  In a custom type, read `get()` for what it does and `value` (the player's own) in `toJson`, `parse` and
  `valueString`, so overrides work.
</Callout>
