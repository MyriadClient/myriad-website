# Windows, HUD and widgets

Everything in the menu is a **panel** inside a window. Panels draw on a `Canvas`: SDF rounded rectangles, gradient
borders, shadows, frosted backdrops and TrueType text, in the player's theme. Icons are glyphs from the bundled Nerd
Font (`""`).

## A window built from widgets

Most windows extend `WidgetPanel` and build their content from widgets. Call `rebuild()` when the structure changes.

```java
public final class WaypointsPanel extends WidgetPanel {
    private final WaypointStore waypoints;
    private String name = "";

    public WaypointsPanel(WaypointStore waypoints) {
        this.waypoints = waypoints;
    }

    @Override
    public String title() {
        return "Waypoints";
    }

    @Override
    protected void build(VBox content) {
        waypoints.all().forEach((n, pos) -> {
            HBox row = new HBox(4);
            row.addWeighted(new Label(n + "  " + pos.toShortString()), 1);
            row.addFixed(new Button("Remove", () -> { waypoints.remove(n); rebuild(); }), 50);
            content.add(row);
        });
        HBox add = new HBox(4);
        add.addWeighted(new TextField(() -> name).placeholder("Name").onChange(s -> name = s), 1);
        add.addFixed(new Button("Add here", () -> {
            if (mc.player != null) waypoints.put(name, mc.player.blockPosition());
            rebuild();
        }).accent(), 60);
        content.add(add);
    }
}
```

```java
// in initialize:
PanelType window = ctx.registerPanel("Waypoints", "", () -> new WaypointsPanel(waypoints));
Myriad.ui().openPanel(window);   // from a key action, a command, a module
```

Widgets: `Label` (`.dim()`, `.bold()`), `Button` (`.accent()`), `Toggle`, `Slider`, `Dropdown`, `TextField`
(`.placeholder`, `.onChange`, `.onSubmit`), `ColorPicker`, `KeybindButton`, `RegistryPicker`, `StringListEditor`,
`Collapsible`, `HBox`/`VBox` (`addWeighted`, `addFixed`), `ScrollView`, `Spacer`, `Preview` (below), and `SettingsView.build(settings)`,
which lays out a whole `Settings` like a module's.

## Previews

`Preview` shows something in 3D so the player can see what render settings do to it: `Preview.entity(type)`,
`Preview.player()` (you, with your armour and what you hold), `Preview.block(block)` (as it stands in the world,
chests and shulker boxes included), `Preview.item(stack)` and `Preview.viewModel()` (your first-person hands and held
items as you'd see them right now, View Model's changes included). Drag to turn it, right-drag or Shift-drag to move it, scroll to zoom, double-click to put it back.

Modules that are on draw on every preview as they draw in the world: those in a module's settings, and the Preview
windows players add to a workspace. What your `HighlightEvent.Hand` handlers highlight shows on a preview's hands
the same way. For the rest, handle `PreviewEvent`, posted each frame for each preview drawn. `entity()`, `block()`
(from a block's item) and `viewModel()` say what it shows; `render(look, color)` shows it in your look in the
[render mode](/docs/develop/rendering#showing-things) that's on, as `RenderEvent` does in the world. `box()` is its box in
the preview's coordinates (an entity's hitbox from its feet, a block's cube from the origin) and `shapes()` takes
boxes and lines there, for anything else. The first `render` wins, and `shown()` tells a fallback look (a
highlight for the block you look at, say) to stay off. Preview entities stand where you are, so range checks count
them as near.

```java
@Subscribe(inGame = true)
private void onPreview(PreviewEvent e) {
    int c = e.entity() == null ? 0 : colorFor(e.entity());
    if (c != 0) e.render(look, c);
}
```

A module shows a preview at the top of its settings window by overriding `preview()`; any window can hold one like
any other widget. `decorate((shapes, box, entity) -> ...)` draws on that one preview only, with the same `ShapeBuilder`
calls, for something no module draws.

```java
@Override
public Widget preview() {
    return Preview.entity(EntityTypes.ZOMBIE);
}
```

For full control, extend `Panel` and implement `render(canvas, width, height, mouseX, mouseY)` and the input methods
(`mouseClicked`, `keyPressed`, ...).

| Panel method | |
|---|---|
| `title()`, `subtitle()`, `icon()`, `tooltip()` | what the title bar and hover show |
| `titleControls()` | controls in the title bar (below) |
| `preferredSize(canvas)` | the size a floating window opens at |
| `tick()`, `onOpen()`, `onClose()` | lifecycle |
| `save(json)`, `load(json)` | state kept with the window between sessions |
| `settings` | a panel's own settings, saved with the window, shown on right-click |

## Title-bar controls

A window can put a switch or icon buttons in its title bar, beside float and close. Make them once:

```java
private final List<TitleControl> controls = List.of(
    TitleControl.toggle(() -> store.syncing(), store::setSyncing, () -> "Sync with the server"),
    TitleControl.button(() -> "", store::refresh, () -> "Refresh").visible(() -> store.syncing())
);

@Override
public List<TitleControl> titleControls() {
    return controls;
}
```

## HUD elements

A HUD element is a panel drawn over the game on the HUD workspace. For lines of text, extend `TextHudPanel`: sizing,
alignment, scale and the standard colour options come with it.

```java
public final class PlayerCountHud extends TextHudPanel {
    public PlayerCountHud() {
        super("Player Count", "", HudStyle.Mode.TEXT);
    }

    @Override
    protected void lines(Lines out) {
        int players = preview() ? 1 : mc.getConnection() == null ? 0 : mc.getConnection().getOnlinePlayers().size();
        out.add("Players", String.valueOf(players));
    }
}
```

```java
ctx.registerHud("Player Count", "", PlayerCountHud::new);                       // added from the HUD workspace
ctx.registerHud("Watermark", "", Watermark::new, PanelType.Anchor.TOP_LEFT, 0, 0); // placed on a fresh install
```

`preview()` is true while there's no world (arranging the HUD from the title screen): show sample values;
`alignRight()` while the element sits on the right of the screen, so text grows leftwards. For
drawing of your own, extend `HudPanel` and use `HudStyle` and `ItemHud`.

## The bar and themes

- **Bar widgets** extend `BarWidget` (a side, an order, `width(canvas, height)`, `render(...)`, `mouseClicked(...)`).
  Register with `ctx.registerBarWidget(...)`.
- **Themes**: `ctx.registerTheme(new Theme(ctx.id("sunset"), "Sunset", t -> { t.accent.set(SettingColor.of(0xFFF5A97F)); }))`.
  Unset values come from Myriad's default. `ThemePalette` builds one from a terminal palette.
- **Colours** in your panels and modules should come from the theme: `Myriad.ui().theme().accent.argb()`, and for
  settings, `SettingColor.role(SettingColor.Mode.ACCENT)`.

## Drawing in vanilla screens

`Myriad.ui().draw(guiGraphics, canvas -> ...)` draws with the canvas inside any vanilla screen or tooltip. In a
`Render2DEvent` handler, use `event.canvas()`.

<Callout type="info">
  `Myriad.ui()` is the desktop: `openPanel`, `find`, `windows()`, `confirm(title, message, label, onConfirm, onCancel)`
  for a yes/no dialog, `theme()`, `applyTheme(...)`.
</Callout>
